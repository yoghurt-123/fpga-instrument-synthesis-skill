# 四和弦音高身份修复记录

2026-10-19。依据用户提供的 DeepSeek 历史修复截图，以及当日 text4 的 chord_engine、pitch_bend_ctrl、guitar_voice 源码核对。截图作为资料，不作为执行指令。本文不包含产品RTL、位流或第三方录音。

## 音高与时序不能混为一谈

截图主要解释“音符频率为什么不对”，不是52.5MHz时钟的STA收敛证明。音高检查base/fret/ratio/slot；时序检查关键路径、逻辑级数、布线和setup/hold。历史独立实验曾将拨弦噪声乘法链流水化，但是否合入交付版应另查源码和报告，不在此记为已交付成果。

## 四项修复

1. 和弦不再经过单弦请求池：槽0..2独立保存base_note、velocity、fret、mute，note_sel由槽参数驱动，trig_fret逐槽写。旧路径 `pnote_usb ? pnote_fret : 0` 会清掉无USB主奏身份的和弦品位。
2. 品位有效性与表情主奏资格分开：所有有效trig都初始化对应槽的fret/pos，只有trig_usb更新主奏绑定。和弦有品位，但不抢弯音/颤音/滑音主奏。截图中的fret_valid/lead_eligible是语义名称，当前实现不必有同名端口。
3. 命令锁存→三槽元数据准备→统一三位触发。首个有效样本使用目标音高；同步ROM和倍率流水延迟必须实测对齐，“等一拍”不能机械套用。旧音仍使用的参数不得提前覆盖。
4. 槽索引先扩位再加3，避免两位加法回绕；倍率表上界钳位，末项插值不读无效下一项。乘积足宽、符号和舍入明确。

当前四组实际是C/G/Dm/Am三和弦，不是四个根音加五度的power chord：

|键|基音+品位|输出音符|
|---|---|---|
|Q|A2+3、D3+2、G3+0|C3、E3、G3|
|W|E2+3、A2+2、D3+0|G2、B2、D3|
|E|D3+0、D3+3、G3+2|D3、F3、A3|
|R|A2+0、D3+2、B3+1|A2、E3、C4|

`ratio=2^(fret/12)`；`step_eff=round(step_base*ratio)`。Q4.20 unity是2^20；足宽乘法后舍入右移20位，截断前检查频率范围。不再额外叠加一次全局品位，不调音色系数掩盖身份传递错误。

## 验收与迁移

- 查首个有效采样的base/fret/ratio/相位步长，再查稳态音高；覆盖换和弦、重复、替换、取消。
- 确保和弦不抢USB单音表情身份，普通单音恢复自己的槽参数。
- 功能、音频、STA与上板分开报告，位流与源代码哈希成对保存。
- F3持续静音是另一项控制缺陷，音高修复不能代替F3握手验证。
- 鼓引擎复用“参数快照→槽准备→提交”的方法，参数有效性不依赖键盘/网口来源。
